# CLAUDE.md — autonomist

An AI organizer for an autonomous cooperative federation: the engine model, a public site, and a chat
agent on Claude Haiku 5.5. Jason Edelman's project, a sibling of Siren (`jedelman/socrata-agent`):
"More radical than Siren, more action-focused." Read `README.md` first; the design paper is
`content/model/the-engine.md`.

## Non-negotiables

- **A public-interest project, plainly.** Every page says so (the band and footer in
  `site/layout.html`; `/about/`). autonomist sells nothing, offers no securities, gives no investment,
  financial, legal or tax advice, holds no money, and files or signs nothing. Keep all of that true in
  code, copy and prompts.
- **Numbers come from code.** The model chooses tool inputs; `model/lec-core.cjs` computes. A saved
  result is re-computed from its inputs in `worker/tools.js` before it's stored; never store
  model-written numbers or prose on a public page (only a cleaned title).
- **Buildings, not people.** `norfolk_parcel` takes an address only; never add a lookup by name. Homes
  (property classes 500s) never show an owner or sale price; an owner shows only on 400-class parcels
  and only when plainly an organization (`shownOwner` in `worker/parcel.js`, tested). Don't loosen
  these without Jason.
- **Case studies are reviewed.** The agent can only propose one (`proposal:` keys in KV); a person
  checks every source before a markdown file is added to `content/case-studies/`. Case files naming a
  real building, its owner or a negotiating position stay private (Jason's claude-memory
  `handbook-cases/`) unless he decides otherwise.
- **Scenario inputs are labeled as scenarios.** The model is a mechanism model, not a forecast.
  `model/results.md` is generated by `node model/run.mjs`; rerun it after any model change and reread
  the prose between its tables.
- **Strict CSP.** No inline script, style attribute or handler anywhere (`worker/index.js` sets the
  policy on every response). Text from users or the model is escaped (`site/js/md.js`; chat links survive
  only for this site, Power Explained, the repo, or a source the server returned).
- **Fails closed.** Without the KV binding or secrets the chat refuses; spend is capped per day across
  the site (`DAILY_BUDGET_USD`) and priced per call (`PRICES` in `worker/limits.js`; a model with no
  price is refused).
- **The steward's page is behind Cloudflare Access** (Jason, 2026-11-20). `worker/admin.js` verifies the
  Access JWT on every `/api/admin/*` request (`worker/access.js`, from Siren); never trust the plain
  email header, and never add a password or token sign-in beside it. Off (404) without
  `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD`.
- **A public agent** (Jason, 2026-11-20). Design: `content/model/the-public-agent.md`. His rules:
  - "ONLY the agent writes the memory." No person, steward included, edits it; corrections are new
    turns, and the summarizer (`worker/memory.js`) may use only what the conversation says.
  - "All user interactions with the agent are public." Questions, answers and how they were reached
    (tools, inputs, results, sources) are a public record. The chat notice, the about page and the
    system prompt say so.
  - "The agent holds no authority to act - merely to aggregate and process data. The data is public
    and portable." Never give it a tool that files, signs, pays, sends or decides for anyone.
  - "Questions and reasoning are queryable and portable. atproto fits." Records go toward atproto,
    under `org.jason-edelman.autonomist.*` (proposed); keep the stored shape exportable.
  - "Nothing that's publication-risk should ever go to the agent. Disclaim but don't gate." Warn
    plainly everywhere people type; add no review gate in front of the conversation.
- **One conversation per invite, with the agent's memory.** `worker/thread.js` keeps it in KV as
  `thread:<invite hash>`: questions, answers, each answer's sources and saved results, and the memory.
  Not yet the trace (tools, inputs, results): it joins the record with the public pages. Never raw
  thinking. When the turns after the memory pass `HISTORY_CHARS`,
  `memory.js` folds the oldest into a plain-text summary (a separate priced call, after the answer,
  under the day's spend cap). The model sees the memory, inside the first user message (never the
  system prompt), then every later turn. Not the API's compaction blocks: the memory must stay
  readable, downloadable and portable across models. No "new conversation" button; "Download my
  conversation" and "Erase my conversation" (withdrawal) stay. Revoking an invite erases its thread;
  a year unused expires it.
- **The agent's own PDS** (Jason, 2026-11-21: "we should use it, and we should help maintain it").
  autonomist's atproto account lives on a PDS this Worker runs: pds.js (`@pdsjs/cloudflare`, MIT,
  pinned exactly; upstream calls itself experimental). `worker/main.js` sends `HOSTNAME`
  (`pds.autonomist.jason-edelman.org`) to pds.js and everything else to the site; the site's
  `/.well-known/atproto-did` reads the DID from the PDS, so the handle `autonomist.jason-edelman.org`
  has one source of truth. One account only, the agent's.
  - `PDS_PASSWORD` gates `/init` until the account exists; without it `/init` is open to anyone.
    It was set before the first deploy carrying the PDS (2026-11-21). Never deploy the PDS to a
    Worker without it.
  - The DID's first rotation key is a recovery key whose private half Jason holds (made at
    `admin.jason-edelman.org/keys/`). The signing key is made by `scripts/birth.mjs` in memory and
    lives only in the PDS. Never write it to disk or print it.
  - `worker/account-ui-stub.js` and the `[alias]` stand in for `@pdsjs/account-ui`, which isn't on
    npm (2.5.2); remove both when it is.
- **The news journal** (Jason, 2026-11-23: "I'd like to get autonomist reading the news and journaling
  commentary from the power explained perspective"). Entries are `content/journal/YYYY-MM-DD-<slug>.md`,
  rendered at `/journal/`, in five sections: What it says; Through Power Explained; What it means for the
  federation; What we don't know; A question to take to your neighbors.
  - Text in curly quotes (“…”) is verbatim from a source listed in `sources:`, and nothing else uses curly
    quotes. `node scripts/journal-check.mjs --fetch` must pass before an entry merges.
  - Figures are the source's, attributed, and a model's outputs are labeled as scenario outputs.
  - The reading cites Power Explained's public pages, and says when it's an inference, not a position the
    project has taken.
  - Take only what's offered, as the research watch does: honor robots.txt and Content-Signal, never get around
    a paywall or block, quote briefly and link, and remove a quotation when a publisher asks.
  - Automated since 2026-11-23 (below): autonomist writes one a day as a record in its own repository.
- **autonomist on Bluesky** (Jason, 2026-11-23: "Opt out for sources, starting with my follows. Cadence: one blog post a
  day, automatic. For Bluesky: like pinned post to opt in to unsolicited opinions. Autonomist posts problem posing
  questions and engages with all replies."). `worker/bot/`, run by the cron every five minutes; off unless `BOT_ENABLED`.
  - **Sources:** the links that accounts `BOT_SOURCE_ACTOR` follows share (`sources.js`), read only when robots.txt and
    Content-Signal allow (opt-out, as the research watch).
  - **The journal, daily and automatic** (`journal.js`): entries are `org.jason-edelman.autonomist.journal` records
    in its repository, rendered at `/journal/<slug>/` (`journal-pages.js`). This is the one place model-written prose
    goes on a public page. It's published only when `checkDraft` passes: every quotation verbatim in the article or a
    `framework.js` passage, every figure present in them, the five sections, no links or @handles. Otherwise the day
    is skipped. `node scripts/journal-check.mjs --framework` checks the passages against the live site.
  - **Replies** (`replies.js`): every reply and mention, in its thread. One answer per post; at most 8 a thread a day,
    2 with self-labeled bots, `BOT_REPLIES_DAILY` in all; "skip" for spam or abuse.
  - **Opt-in** (`optin.js`): the accounts that like the pinned post may get a reply on their own posts, at most one a
    day each and `BOT_OPTIN_DAILY` in all. Unliking ends it at the next hourly refresh.
  - **Never:** follow, like, repost, DM, @-mention (no mention facets), link beyond this site and Power Explained, or
    reply unasked to anyone who hasn't opted in.
  - **Spend:** `BOT_DAILY_BUDGET_USD`, inside the site's `DAILY_BUDGET_USD`. Model calls ask for JSON against a schema
    (`output_config.format`), which works with Haiku 5.5's thinking.
  - **Session:** kept in KV and refreshed; it logs in only for a token pds.js won't accept, and counts logins
    (`bot:logins:<day>`).
- **Keep these projects separate unless Jason links them:** Ghent Streets (Jason, 2026-11-20).

## Layout

- `model/` the engine model (Node and browser), its driver and generated results.
- `worker/` the Worker: `main.js` (the entry: the PDS's host to pds.js, the rest to the site), `index.js` (the site's routes, limits, headers), `admin.js` and `access.js` (the steward's page), `agent.js` (the tool loop, the system
  prompt), `thread.js` and `memory.js` (each invite's one conversation and its memory), `tools.js` (tool schemas and executors), `parcel.js` (Norfolk open data, fields checked live
  2026-11-20), `invites.js` and `limits.js` (adapted from Siren's, MIT), `journal-core.js` (the journal's checks, shared with
  the script), `journal-pages.js` (pages for entries in its repository), `bot/` (autonomist on Bluesky).
- `site/` the layout, pages (markdown), tool pages and scripts, chat; `content/` papers, case
  studies and the journal; `scripts/build.mjs` renders it all into `public/` (git-ignored; wrangler builds it on
  deploy); `scripts/invites.mjs` the steward's CLI; `scripts/birth.mjs` gives an agent its account on its own PDS
  (autonomist's by default; `--handle` and `--pds` for another agent, `--dry-run` to only build the
  genesis operation); `scripts/journal-check.mjs` checks the journal (`--fetch` checks every quotation against its
  source; `--can <url>` says whether autonomist may read a page).
- `test/` `npm test` (node:test; no network).

## Checks before pushing

```bash
npm test
node scripts/build.mjs
node scripts/journal-check.mjs --fetch   # when a journal entry changed
node scripts/journal-check.mjs --framework   # when worker/bot/framework.js changed
npx wrangler deploy --dry-run --outdir /tmp/autonomist-dist
```

To try the PDS locally, `wrangler dev` needs a config without `routes` (with them it rewrites every
request's host): copy `wrangler.toml` to `.wrangler-test.toml` (git-ignored) minus the `routes`
block, then `npx wrangler dev -c .wrangler-test.toml --var HOSTNAME:localhost --var
PDS_PASSWORD:<test> --var JWT_SECRET:<test>`. `localhost` is the PDS; `127.0.0.1` is the site.
