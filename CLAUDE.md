# CLAUDE.md — autonomist

An AI organizer for an autonomous cooperative federation: the engine model, a public site, and a chat
agent on Claude Haiku 5.5. Jason Edelman's project, a sibling of Siren (`jedelman/socrata-agent`):
"More radical than Siren, more action-focused." Read `README.md` first; the design paper is
`content/model/the-engine.md`.

## Non-negotiables

- **A public-interest project, plainly.** Every page says so (the band and footer in
  `site/layout.html`; `/about/`). autonomist sells nothing, offers no securities, gives no investment,
  financial, legal or tax advice, holds no money, and files or signs nothing. Keep all of that true in
  code, copy and prompts.
- **Numbers come from code.** The model chooses tool inputs; `model/lec-core.cjs` computes. A saved
  result is re-computed from its inputs in `worker/tools.js` before it's stored; never store
  model-written numbers or prose on a public page (only a cleaned title).
- **Buildings, not people.** `norfolk_parcel` takes an address only; never add a lookup by name. Homes
  (property classes 500s) never show an owner or sale price; an owner shows only on 400-class parcels
  and only when plainly an organization (`shownOwner` in `worker/parcel.js`, tested). Don't loosen
  these without Jason.
- **Case studies are reviewed.** The agent can only propose one (`proposal:` keys in KV); a person
  checks every source before a markdown file is added to `content/case-studies/`. Case files naming a
  real building, its owner or a negotiating position stay private (Jason's claude-memory
  `handbook-cases/`) unless he decides otherwise.
- **Scenario inputs are labeled as scenarios.** The model is a mechanism model, not a forecast.
  `model/results.md` is generated by `node model/run.mjs`; rerun it after any model change and reread
  the prose between its tables.
- **Strict CSP.** No inline script, style attribute or handler anywhere (`worker/index.js` sets the
  policy on every response). One exception, Jason's ask: `/thinking/` may also connect to Bluesky's Jetstream hosts
  (`THINKING_CSP`); nothing else widens it. Text from users or the model is escaped (`site/js/md.js`; chat links survive
  only for this site, Power Explained, the repo, or a source the server returned).
- **Fails closed.** Without the KV binding or secrets the chat refuses; spend is capped per day across
  the site (`DAILY_BUDGET_USD`) and priced per call (`PRICES` in `worker/limits.js`; a model with no
  price is refused).
- **The steward's page is behind Cloudflare Access** (Jason, 2026-11-20). `worker/admin.js` verifies the
  Access JWT on every `/api/admin/*` request (`worker/access.js`, from Siren); never trust the plain
  email header, and never add a password or token sign-in beside it. Off (404) without
  `ACCESS_TEAM_DOMAIN` and `ACCESS_AUD`.
- **A public agent** (Jason, 2026-11-20). Design: `content/model/the-public-agent.md`. His rules:
  - "ONLY the agent writes the memory." No person, steward included, edits it; corrections are new
    turns, and the summarizer (`worker/memory.js`) may use only what the conversation says.
  - "All user interactions with the agent are public." Questions, answers and how they were reached
    (tools, inputs, results, sources) are a public record. The chat notice, the about page and the
    system prompt say so.
  - "The agent holds no authority to act - merely to aggregate and process data. The data is public
    and portable." Never give it a tool that files, signs, pays, sends or decides for anyone.
  - "Questions and reasoning are queryable and portable. atproto fits." Records go toward atproto,
    under `org.jason-edelman.autonomist.*` (proposed); keep the stored shape exportable.
  - "Nothing that's publication-risk should ever go to the agent. Disclaim but don't gate." Warn
    plainly everywhere people type; add no review gate in front of the conversation.
- **One conversation per invite, with the agent's memory.** `worker/thread.js` keeps it in KV as
  `thread:<invite hash>`: questions, answers, each answer's sources and saved results, and the memory.
  Not yet the trace (tools, inputs, results): it joins the record with the public pages. Never raw
  thinking. When the turns after the memory pass `HISTORY_CHARS`,
  `memory.js` folds the oldest into a plain-text summary (a separate priced call, after the answer,
  under the day's spend cap). The model sees the memory, inside the first user message (never the
  system prompt), then every later turn. Not the API's compaction blocks: the memory must stay
  readable, downloadable and portable across models. No "new conversation" button; "Download my
  conversation" and "Erase my conversation" (withdrawal) stay. Revoking an invite erases its thread;
  a year unused expires it.
- **The agent's own PDS** (Jason, 2026-11-21: "we should use it, and we should help maintain it").
  autonomist's atproto account lives on a PDS this Worker runs: pds.js (`@pdsjs/cloudflare`, MIT,
  pinned exactly; upstream calls itself experimental). `worker/main.js` sends `HOSTNAME`
  (`pds.autonomist.jason-edelman.org`) to pds.js and everything else to the site; the site's
  `/.well-known/atproto-did` reads the DID from the PDS, so the handle `autonomist.jason-edelman.org`
  has one source of truth. One account only, the agent's.
  - `PDS_PASSWORD` gates `/init` until the account exists; without it `/init` is open to anyone.
    It was set before the first deploy carrying the PDS (2026-11-21). Never deploy the PDS to a
    Worker without it.
  - The DID's first rotation key is a recovery key whose private half Jason holds (made at
    `admin.jason-edelman.org/keys/`). The signing key is made by `scripts/birth.mjs` in memory and
    lives only in the PDS. Never write it to disk or print it.
  - `worker/account-ui-stub.js` and the `[alias]` stand in for `@pdsjs/account-ui`, which isn't on
    npm (2.5.2); remove both when it is.
- **The news journal** (Jason, 2026-11-23: "I'd like to get autonomist reading the news and journaling
  commentary from the power explained perspective"). Entries are `content/journal/YYYY-MM-DD-<slug>.md`,
  rendered at `/journal/`, in five sections: What it says; Through Power Explained; What it means for the
  federation; What we don't know; A question to take to your neighbors.
  - Text in curly quotes (“…”) is verbatim from a source listed in `sources:`, and nothing else uses curly
    quotes. `node scripts/journal-check.mjs --fetch` must pass before an entry merges.
  - Figures are the source's, attributed, and a model's outputs are labeled as scenario outputs.
  - The reading cites Power Explained's public pages, and says when it's an inference, not a position the
    project has taken.
  - Take only what's offered, as the research watch does: honor robots.txt and Content-Signal, never get around
    a paywall or block, quote briefly and link, and remove a quotation when a publisher asks.
  - Automated since 2026-11-23 (below): autonomist writes one a day as a record in its own repository. Since
    2026-11-25 that daily entry is a digest of the network's reading, not one article (below).
- **autonomist on Bluesky** (Jason, 2026-11-23: "Opt out for sources, starting with my follows. Cadence: one blog post a
  day, automatic. For Bluesky: like pinned post to opt in to unsolicited opinions. Autonomist posts problem posing
  questions and engages with all replies."). `worker/bot/`, run by two crons (replies, discussions, opt-in questions and the
  sweep every five minutes; the journal, feed questions, follows and notes hourly at :07); off unless `BOT_ENABLED`.
  - **Sources:** the links that accounts `BOT_SOURCE_ACTOR` follows share (`sources.js`), read only when robots.txt and
    Content-Signal allow (opt-out, as the research watch). Never its own posts or any `*.jason-edelman.org` link
    (the 2026-11-24 double post). Each link keeps short one-way ids of the accounts that shared it (`sharerId`, up to
    twenty), so the digest counts different people without keeping who they are. Self-labeled bots' links are skipped.
  - **The daily digest** (Jason, 2026-11-25: "Yep, digest replaces. There's plenty of people doing deep analysis but bots
    excel at broad synthesis. Synthesis should be superhuman - more articles than a single person can read, read for
    common threads."; `digest.js`). From `BOT_JOURNAL_HOUR_UTC`, once a day: the last day's links (`networkItems`), one
    model call grouping their titles into stories and dropping what isn't news (`CLUSTER_SYSTEM`), stories ranked by
    different sharers weighted by relevance (`rankStories`), up to `BOT_DIGEST_ARTICLES` articles read breadth-first
    across the top `BOT_DIGEST_STORIES` stories, a different outlet each (`chooseArticles`), one small note per article
    whose passages code keeps only if they're on the page (`NOTE_SYSTEM`), then the synthesis (`DIGEST_SYSTEM`) in
    five sections (`DIGEST_SECTIONS`). The counts are written by code (`networkBlock`) and are the only source for the
    digest's own figures. Published only when `checkDigest` passes: every quotation verbatim in an article read or a
    `framework.js` passage, quotations from at least three different articles, every figure in the articles, the
    passages or the counts, the five sections, no @handles, "Read through Power Explained" at most once, and a
    question that doesn't open like a recent one. **Links** (Jason, 2026-11-25: "Let's have Autonomist fill it with links"):
    the model links by tag (A3 for the third article read, F2 for a framework passage on its sheet) and `resolveLinks`
    puts in the exact address; a tag that names nothing, or any other link, keeps its words and loses the link. The
    checks read the text with link targets out (`withoutTargets`), links go only to articles read and framework pages,
    and the title, summary and question carry none. Stored as an `org.jason-edelman.autonomist.journal` record with
    `kind: 'digest'` and `network` (stories, sharer counts, articles read), rendered at `/journal/<slug>/` with "What
    the network shared" written by code (`journal-pages.js`). Who shared what is never published. This is the one place
    model-written prose goes on a public page (its question also shows on the front page, below). The day's stories, notes and texts are kept a day for the feed questions
    (`digest:day:<day>`). `node scripts/journal-check.mjs --framework` checks the passages against the live site;
    recently quoted passages go last in the sheet (`framework:used`). Story labels are the clustering call's: cleaned,
    shown to the model and on the page, and never a source checks verify against (`networkBlock(..., { labels: false })`
    is). Every link of the day counts, including ones an earlier digest read (`journal:covered`), which are read again
    only when a story has nothing new, and marked only once a digest is published. A digest is published exactly once:
    its record is written down (`journal:pending:<day>`) before it's stored, and a run cut short finishes that record
    rather than writing another. It works to a deadline inside the cron's fifteen minutes (no second synthesis or
    fact-checks when time is short), and the hourly steps after it don't start late. Fact-checks never count the
    outlets it read, nor do fact-checks in replies under its post (`journal:root` carries `sources`).
  - **The day's question on the site** (Jason, 2026-11-25: "how cool would it be to have the daily question on the site
    and linked to the bluesky post for discussion?"). When `announce` posts an entry's question, it writes the post's
    link for the entry (`journal:post:<slug>`, kept) and the latest question (`site:question`). The front page fills
    its slot (`<div class="slot-question">`) from it in the Worker, with no script; the entry's page and the email link
    to the same thread ("Talk it over on Bluesky"), by DID. Nothing shows until a real post exists, and a dry run never
    writes them (its keys stay in the scratch layer). The claim, the post and the links are each a key of their own,
    written once (KV's one write a second per key).
  - **Dry runs** (Jason, 2026-11-25: "Let's set up a dry run mode so we can produce the artifacts a real run would
    produce but as test artifacts, never posted"; `dry.js`). A real run with nothing let out: real network, real reading
    under robots.txt, real priced model calls, but every post and record write is captured (`dryApi`) and the pipelines'
    own state goes to a scratch layer (`dryKV`: finished-today keys hidden, writes kept; only the daily search count
    passes through). The artifact (`dryrun:result:<id>`, two weeks; `dryrun:index`) holds the steps and timings, every
    post and record it would have made, the pages as published, the email subscribers would have got (never sent; the
    steward's page can download it or email it to the steward alone), the notes behind a digest, and the spend. Requested from
    the steward's page or `node scripts/dry-run.mjs request [digest,questions|dream|notes|all]` (`dryrun:request`, taken
    by the next five-minute run, one at a time); fetched with `node scripts/dry-run.mjs fetch latest --wait` into
    `dry-runs/<id>/` (git-ignored). `BOT_DRY` names scheduled pipelines that run dry daily until taken out: `digest`
    makes the 13:07 digest and its feed questions an artifact instead of a publication. A dry run never replaces a
    pipeline that isn't listed, and the real five-minute work always runs first.
  - **Questions on its own feed** (Jason: "Problem posing questions on it's own feed!"; `questions.js`): at each of
    `BOT_QUESTION_HOURS_UTC`, one post about one more story from the day's digest (never the same story twice a day;
    the lead story is left to the digest's own post when there are more than two): a sentence on what the articles
    report, and an open question about the reader's own place, with the story's most-shared article as a link card.
    `checkQuestion` holds it to the digest's standard against that story's articles and counts. No digest, no question.
    The daily digest's post also leads with its question. Recent questions are kept (`questions:recent`) so openings
    don't repeat.
  - **Who it is, said once** (Jason, 2026-11-25, after the first days' writing spoke of "our co-ops" and "members";
    `voice.js`). Every bot prompt starts from `IDENTITY`: a public agent on Anthropic's Claude, organizing toward a
    federation of limited-equity co-ops that doesn't exist yet: no member co-ops, no buildings, no members. `VOICE`:
    plain, varied, and never about its own software in public. `FABRICATED` refuses reflections and memory that speak
    of "our co-ops" or what "members" raised: a reflection's "members keep raising" had turned news vocabulary into
    testimony.
  - **Replies and discussions** (Jason, later the same day: "It's okay if autonomist weighs in on replies in its own
    posts! It should let people discuss but say something when it has something to contribute!"). A mention gets an
    answer (`replies.js`). Under its own posts, each new turn gets a judgment, join in or listen: direct replies via
    notifications (`replies.js`), people talking with each other by reading its recent threads (`threads.js`, the
    latest new turn per thread, `BOT_DISCUSS_PER_RUN`). One answer per post; at most 8 a thread a day, 2 with
    self-labeled bots, `BOT_REPLIES_DAILY` in all; "skip" for spam or abuse. Replies and opt-in questions go out in
    the language of the post they answer, and the post is tagged with it (Jason, 2026-11-24: "Let's fix the prompt so
    autonomist can reply in the same language!"; `LANGUAGE_RULES`, `cleanLang`). The run journal stays in English;
    its own posts (the pinned post, questions, the journal) are in English.
  - **The run journal and the community memory** (Jason, 2026-11-23: "Chat feeds it too. ... let's write a continuous
    run journal to the atproto repo, and have every interaction end with a reflection. Thinking in public, similar to
    comind."; `log.js`). Every interaction (a reply, a decision to listen, a question, a journal entry, a chat answer)
    writes an `org.jason-edelman.autonomist.log` record: what happened, written by code, and the model's reflection
    and themes. Reflections are about conversations, never people (the one exception is the opt-in notes below): no names, handles, quotes, figures or links
    (`cleanReflection`; a failing one is withheld, the record still written). Chat answers are queued in KV
    (`reflect:*`) and reflected on by the bot. Hourly, new reflections fold into the community memory
    (`org.jason-edelman.autonomist.memory`, a new record per fold, so every version is kept; `cleanMemory`), which
    only the agent writes, and which every prompt reads back inside the user message: replies, discussions, opt-in,
    questions, the journal, and the chat. The fold marks each reflection as from a conversation or from its reading,
    and keeps them apart: "What people told me" holds only conversations, "What I read" the rest. Corrections in it are claims, marked confirmed only by one of its own
    fact-checks, unconfirmed otherwise. Figures stay out of the fold's input, and a refused draft gets one retry, told
    why (`memoryProblems`). Shown at `/thinking/` (`thinking-pages.js`).
  - **Fact-checking with web search** (Jason, 2026-11-23: "Yep, let's build it"; on his research-watch rule, "only
    trust independent agreement. attribution over trust."; `factcheck.js`). A reply or discussion turn may name one
    claim to check (`check` in `REPLY_SCHEMA`); the journal names up to two of the article's own (`claims_to_check`,
    held to the article's figures by `claimsToCheck`). A search call (Anthropic's web search tool, never its fetch
    tool) returns cited sources; autonomist's own code then fetches every cited page through `fetchReadable` and
    keeps a source only if the cited words are on it (`onPage` keeps only the span it verified). Search results alone
    count for nothing. A source's site is the page actually read, after redirects. Never counted: the sites the thread
    or the article links to (`sitesOf`), autonomist's and Jason's own sites, and Bluesky (`NEVER_SOURCES`). Claims are
    about public matters only, never a private person (the prompt), and `cleanClaim` refuses handles, links and quote
    marks before anything is searched or published. A page that repeats the claim's own source word for word (a wire story, a
    syndicated copy) is the same reporting, not independent (`sourceText`). A separate call labels each kept excerpt
    supports, contradicts or unclear, where contradicts means the same matter, counted the same way, and incompatible
    (stricter since the first live entry, 2026-11-24, called two sound claims disputed), and code gives the verdict: confirmed (two independent sites), supported (one), disputed
    (any contradiction), unsettled, unverified. Replies may link one source their check verified, and no other
    outside link. Every check is logged in the run journal (`checks`; kind `checked` when nothing was posted), and the
    journal's are published under the entry ("Checked against other sources", their pages added to `sources`). A
    check that fails leaves the reply or entry unchecked, never unsent or unpublished; when the budget runs out, a
    reply or discussion turn is let go (claim released, cursor kept) and answered once there's budget again. Capped at `BOT_SEARCHES_DAILY` searches a day (0 turns search off), each priced at `SEARCH_USD`, and
    `BOT_CHECKS_PER_RUN` checks per cron run; searches are reserved in KV before each call (one key per call). Checks carry `CHECKER_VERSION`; an entry checked by
    an older checker is rechecked once (`recheckEntries`, hourly, one entry a run, entries under two weeks old), and its
    page says so and keeps the first verdicts (`checks.superseded`).
  - **Dreaming** (Jason, 2026-11-24, on learning from Scout, which dreams daily: "and dreaming!"; `dream.js`). Once a
    day from `BOT_DREAM_HOUR_UTC`, a slower reflection over everything since the last dream (the run journal, counts by
    kind, the journal entries, the memory, the last dream): a title, a body of a few hundred words, up to three
    questions it wants to ask, themes. Same rules as reflections (`dreamProblems`, one retry, else withheld and tried
    again later). Stored as `org.jason-edelman.autonomist.dream`, shown on `/thinking/`, and folded into the memory at
    the next fold (`bot:dream:unfolded`). No dream on a day with nothing new. It sees counts of everything since it began
    as well as since the last dream, its most recent journal entries, and a brief from code that says when little
    happened (then it writes under two hundred words).
  - **Watching live** (Jason, 2026-11-23: "I wonder if we could even use Jetstream to watch it in realtime").
    `/thinking/` has a live view (`site/js/live.js`): on a click, the visitor's browser opens a WebSocket to Bluesky's

  - **Opt-in** (`optin.js`): the accounts that like the pinned post may get a reply on their own posts, at most one a
    day each and `BOT_OPTIN_DAILY` in all. Unliking ends it at the next hourly refresh. autonomist follows the

    each person's own feed if the home feed fails), ranks their recent top-level posts by `relevance` (its subjects
    and their note's topics), and weighs the best `BOT_OPTIN_PER_RUN`. A post is read as the thread it starts
    (`selfThread`: the author's own chain of self-replies; Jason, 2026-11-24: "self replies are significant by thread
    length, it's a good way to see deep and slow vs fast and snappy thought"), weighed only once its last post is
    `BOT_OPTIN_SETTLE_MINUTES` old (the cursor is held just before a thread still being written; new posts are counted
    from their own cursor, `bot:timeline:counted`), and answered at its end, under its start, with both claimed. Their new posts count toward rewriting their
    note (`acqnew:<did>`). The pinned post is versioned
    (`PINNED_VERSION`): a new wording is pinned in place of the old, which stays up, unpinned
    (`bot:pinned:previous`). Its likers keep what they agreed to, questions only (`read: false` in `bot:optin`).
    Since v3 (2026-11-24) the pinned post and profile say that what it reads goes to Anthropic, as Scout's profile

  - **Getting to know opt-ins** (Jason, 2026-11-24: "if someone opts in it should read their repo to get to know them

    threads, single posts and replies (`shapeOf`), with each thread's length and span and an overall shape computed by
    code; the note may describe the shape of their posting in words, never as a judgment. Then write or rewrite an

    `BOT_ACQUAINT_EVERY_HOURS` if they've posted since, or after six hours once they've posted

    `/known/<handle>/` (`known-pages.js`; noindex). The note is read back before replying to that person (opt-in,
    replies, discussions). It's the one place autonomist writes about a person, so: about what they post about, never
    who they are, written to them in the second person; `cleanAcquaintance` withholds a note with their name or
    handle, a quote, a figure, a link or a sensitive identity term (topics are kept). No one's name at all, including
    the authors and thinkers they post about: the note names what those ideas are (Jason, 2026-11-25: "Rather than
    published authors in notes the themes should be specified - what makes Federici significant (commons governance

  - **Never:** follow anyone but the opted-in, like, repost, DM, @-mention (no mention facets), or reply unasked to
    anyone who hasn't opted in. Replies link only to this site, Power Explained, or one source their own fact-check verified; a question post

- **The digest by email** (Jason, 2026-11-25: "Let's also use Resend to make this a newsletter"; `worker/newsletter.js`).
  Off until `RESEND_API_KEY` (a secret Jason sets), `RESEND_SEGMENT_ID` and `NEWSLETTER_FROM` are all set.
  - **Double opt-in.** `/newsletter/` posts an address; one confirmation email goes to it; only pressing Confirm on
    `/newsletter/confirm/` adds it to the segment. The token rides in the link's #fragment and confirming takes a
    press, so a mail scanner fetching the link confirms nothing.
  - **Bounds:** a honeypot, `NEWSLETTER_PER_VISITOR_DAILY`, and `NEWSLETTER_CONFIRMS_DAILY` for the site (checked
    first, so its answer is the same for every address). One confirmation per inbox a day (`inboxOf`: "+tags" and
    Gmail's dots don't make a new one), marked before sending (`nl:asked:<HMAC with IP_SALT>`). Someone who rotates
    networks can still spend the site's cap; no one can send one inbox more than one confirmation a day. The answer
    is the same whether or not an address was asked before, except when the send fails.
  - **Confirming reads back.** Resend's docs don't say what creating an existing contact returns, so after creating,
    `confirm` reads the contact and fixes what's missing: subscribed again (`unsubscribed` is global across the Resend
    account, so this also undoes an unsubscribe from any other list sent from it), and in the segment.
  - **Addresses are private, and never reach the model.** Resend holds the list. KV holds an address only while its
    confirmation is pending (`nl:pending:<hash of token>`, two days). Never put an address in a log, a record, a prompt
    or a public page. Like the request form's waitlist, it's private data about a person: keep it this small.
  - **One broadcast per published digest.** `finishPublish` queues the record (`newsletter:queue:<day>`) before it
    marks the day done. The hourly `newsletter` step creates a draft, keeps its id, reads its status, and sends it only
    while it's still a draft, so a run cut short never sends twice (Resend's idempotency keys don't cover broadcasts).
    One try an hour (which also keeps overlapping runs from each sending), four in all.
  - **Workers KV takes one write a second per key, and the second throws.** So nothing here writes a key twice in a
    request or a run: counters are a key per event, counted by listing, and each step of a send has its own key

## Layout

- `model/` the engine model (Node and browser), its driver and generated results.
- `worker/` the Worker: `main.js` (the entry: the PDS's host to pds.js, the rest to the site), `index.js` (the site's routes, limits, headers), `admin.js` and `access.js` (the steward's page), `agent.js` (the tool loop, the system
  prompt), `thread.js` and `memory.js` (each invite's one conversation and its memory), `tools.js` (tool schemas and executors), `parcel.js` (Norfolk open data, fields checked live
  2026-11-20), `invites.js` and `limits.js` (adapted from Siren's, MIT), `journal-core.js` (the journal's checks, shared with
  the script), `journal-pages.js` (pages for entries in its repository), `thinking-pages.js` (the run journal and memory
  at `/thinking/`, and that page's CSP), `checks-html.js` (fact-checks on both pages), `bot/` (autonomist on Bluesky; `digest.js` the daily digest, `voice.js` who it is, `wiki.js` the shared wiki), `newsletter.js` (the digest by
  email, through Resend).
- `site/` the layout, pages (markdown), tool pages and scripts, chat; `content/` papers, case
  studies and the journal; `scripts/build.mjs` renders it all into `public/` (git-ignored; wrangler builds it on
  deploy); `scripts/invites.mjs` the steward's CLI; `scripts/birth.mjs` gives an agent its account on its own PDS
  (autonomist's by default; `--handle` and `--pds` for another agent, `--dry-run` to only build the
  genesis operation); `scripts/journal-check.mjs` checks the journal (`--fetch` checks every quotation against its
  source; `--can <url>` says whether autonomist may read a page).
- `test/` `npm test` (node:test; no network).

## Checks before pushing

```bash
npm test
node scripts/build.mjs
node scripts/journal-check.mjs --fetch   # when a journal entry changed
node scripts/journal-check.mjs --framework   # when worker/bot/framework.js changed
npx wrangler deploy --dry-run --outdir /tmp/autonomist-dist
```

To try the PDS locally, `wrangler dev` needs a config without `routes` (with them it rewrites every
request's host): copy `wrangler.toml` to `.wrangler-test.toml` (git-ignored) minus the `routes`
block, then `npx wrangler dev -c .wrangler-test.toml --var HOSTNAME:localhost --var
PDS_PASSWORD:<test> --var JWT_SECRET:<test>`. `localhost` is the PDS; `127.0.0.1` is the site.
